# ベンチマーク結果ページ (tools/bench-site)

CI が計測した Runtime のマイクロベンチマーク (`runtime/bench`) の結果と推移を見るための静的ページです。
master の結果は GitHub Pages に公開され、ブランチの結果は CI のアーティファクト `bench-site` に同じページとして入ります (展開して `index.html` を開けば見られます)。

ビルド手順も外部ライブラリもありません。`index.html` / `app.js` / `style.css` / `favicon.svg` の 4 ファイルと、CI が作るデータ (`data/`) だけで動きます。

## 何が見られるか

- **概要**: 最新の計測 (master の最新、またはプレビュー中のブランチ) の要約
  - 全体の変化 (全ベンチマークの比の幾何平均) と、悪化 / 改善 / ヒープ確保予算 / 計測環境のカード
  - ベンチマークごとの表: 最新値 (1 op あたり)、比較対象 (base) との変化と 95 % 信頼区間、判定、ヒープ確保回数と予算、直近の推移
  - 検索 (`-語` で除外)、グループでの絞り込み、「変化ありのみ」、並べ替え
- **詳細** (行を選ぶと開く): 推移のグラフ (時間 / 確保回数 / 確保バイト、絶対値 / 変化率、範囲の拡大)、最新の計測のラウンドごとの値と比の信頼区間、統計値の表
- **2 コミット比較**: 同じバリアントの 2 つのコミットの中央値を並べて比べる (別々の実行どうしなので目安)
- **読み方**: 計測のしかた (同じ VM で head と base を交互に実行) と判定の基準

コンパイラと構成の組み合わせ (MSVC / ClangCL × Master / Release) は右上で切り替えます。

### 数字の読み方で気を付けること

- 判定 (▲ 悪化 / ▼ 改善) は、同じ VM で交互に動かした head と base の **比** から出しています。VM の当たり外れは両方にかかるので打ち消されます。
- ランナーの CPU は実行ごとに変わることがあります。推移のグラフでは点の色と形で CPU を分け、CPU が違う点どうしの絶対値は比べないでください。表の小さな推移グラフは、最新と同じ CPU の点だけで描いています。
- 時間の悪化は CI を止めません。ヒープ確保回数が予算を超えたときだけ CI が失敗します。

## 手元で見る

データは CI が作るので、手元にはありません。見た目や操作を直すときは、デモデータを作ってから開きます。

```sh
python3 tools/bench-site/make-demo-data.py
# そのままブラウザで tools/bench-site/index.html を開く (file:// で動く)
```

ローカルサーバーで開いてもかまいません。

```sh
python3 -m http.server -d tools/bench-site 8000
# http://localhost:8000/
```

`make-demo-data.py` のオプション:

| オプション | 内容 |
|---|---|
| `--preview` | 最新の結果を「未マージのブランチの計測」にする (プレビューの帯、分岐元との比較、予算違反の例が出る) |
| `--commits N` | master のコミット数 (既定 120)。大きな履歴での速さを見るときは 1500 など |
| `--out-dir DIR` | 出力先 (既定はこのディレクトリの `data/`) |

乱数の種は固定なので、同じ引数なら毎回同じデータになります。`data/` は `.gitignore` 済みです。

`data/` を消すと、データが無いときの表示 (空の状態) を確かめられます。

## URL

状態はハッシュに入るので、そのままリンクとして共有できます。

| 例 | 内容 |
|---|---|
| `#v=msvc-master` | バリアントを選ぶ |
| `#v=msvc-master&b=ecs/query_iterate/10k` | そのベンチマークの詳細を開く |
| `#view=compare&v=msvc-master&a=<sha7>&b=<sha7>` | 2 コミット比較 |

## キーボード

| キー | 動作 |
|---|---|
| `/` | 検索欄へ |
| `j` / `k`、`↓` / `↑` | 表の行を移動 |
| `Enter` | 行の詳細を開く |
| `Esc` | 詳細を閉じる |
| `←` / `→` (グラフにフォーカス中) | 点を移動。`Enter` で GitHub のコミットを開く |

## データの形式

`data/history.js` は `window.NOX_BENCH_HISTORY = {...};`、`data/latest.js` は `window.NOX_BENCH_LATEST = {...};` の 1 行です。`fetch` は `file://` で動かないため、JSON ではなく `<script>` で読める形にしています (`data/history.json` は同じ内容の JSON で、ダウンロード用)。

- `nox-bench-history/1`: master の履歴。ベンチマークごとの列指向の配列 (コミット番号、環境、中央値、四分位、対の比較の比と区間、判定、確保回数など)
- `nox-bench-latest/1`: 直近の実行 1 回分。バリアントごとに `bench-run.py` の結果 (`nox-bench-run/1`) をそのまま持ち、ラウンドごとの値を含む

作るのは `.github/scripts/bench-report.py` です。どちらのファイルも無い、または `null` のときは空の状態を表示します。

## 直すときの約束

- 外部への通信をしない (CDN、Web フォント、解析スクリプトを入れない)。`file://` で開けることを保つ
- 色は `style.css` の `:root` のトークンだけを使う。ダークモードは同じトークンを `prefers-color-scheme` と `data-theme` の両方で上書きしている
- 色だけで意味を伝えない (▲ / ▼ / ≈ / ？ の記号と文字を必ず添える)。グラフには `aria-label` の要約と「表で見る」を付ける
- CPU の色 (`--cpu-*`) の並びは色覚多様性の検証を通したもの。変えるときは検証し直す
- 改行は LF、文字コードは BOM なしの UTF-8
